# [PRD] 어디살래? — 부동산 급지 대결 커뮤니티
**버전:** v1.1
**상태:** Draft / MVP 개발 기준
**핵심 원칙:** 모바일 퍼스트 · 빠른 상호작용 · 데이터 구조화 · 향후 AI 아카이빙

## 1. Product Overview
### 1.1 서비스명
어디살래? (Live & Buy)

### 1.2 한 줄 소개
“어디에 살지, 어디가 더 나은지 붙어보자.”
지역·아파트·생활권을 A vs B 구도로 비교하고, 사용자들이 투표와 토론을 통해 실거주 및 투자 관점의 정보를 축적하는 부동산 커뮤니티.

### 1.3 비전
기존 부동산 커뮤니티는 정보가 게시물 단위로 흩어져 있고, 시간이 지나면 묻히며 모바일 사용성이 불편하다는 문제가 있다.
**어디살래?**는 이를 다음 구조로 해결한다.
`지역/단지 비교 → A vs B 대결 → 투표 + 댓글 토론 → 핵심 주장/데이터 축적 → AI 요약 및 구조화 → 검색 가능한 부동산 정보 자산`

### 1.4 핵심 가치
* **사용자 관점:** 쉽게 비교하고, 재미있게 참여하며, 논쟁 속에서 유용한 정보를 발견한다.
* **서비스 관점:** 높은 참여율을 만들고, AI를 통해 토론을 정제하여 검색 가능한 장기 콘텐츠 자산으로 전환한다.

## 2. Product Principles
* **Principle 1. Mobile First:** Desktop보다 모바일에서의 사용성을 우선한다.
* **Principle 2. Speed First:** 게시글 목록 → 게시글 → 댓글 → 투표까지 최대한 빠르게 이동한다.
* **Principle 3. Low Friction:** 불필요한 입력을 최소화한다.
* **Principle 4. Structured Data:** 향후 분석할 수 있도록 데이터 구조를 최대한 보존한다.
* **Principle 5. Community First, AI Second:** AI는 커뮤니티에서 생성된 콘텐츠를 정리하는 역할을 한다.
* **Principle 6. MVP는 작게:** `게시글 작성 → 댓글/추천 → 다른 글 참여` 코어 루프에 집중한다. A vs B 대결(투표)은 사람이 모인 뒤 전용 게시판을 추가하는 방식으로 확장한다(Phase 2).

## 3. Target Users & Persona
* **Primary User:** 특정 지역의 실거주를 고민하거나 아파트/지역을 비교하는 것을 좋아하는 사람.
* **Persona A (실거주 고민형):** 교통, 학군, 상권, 직주근접 중시.
* **Persona B (투자 비교형):** 가격 상승 가능성, 정비사업, 호재, 거래량 중시.
* **Persona C (커뮤니티 참여형):** 투표, 논쟁, 인기글 중심.

## 4. MVP Scope
### 4.1 반드시 포함할 기능
* **사용자:** 이메일 가입(이메일 + 비밀번호 + 닉네임). 소셜 로그인(Google/Kakao)은 Phase 2.
* **게시판:** MVP는 일반 게시판 1개(자유게시판)로 시작한다. 스키마는 다중 게시판(`boards`)을 전제로 설계해, 이후 게시판 추가가 마이그레이션 없이 가능하게 한다.
* **게시글:** 목록, 상세, 작성/수정/삭제, 이미지 업로드, URL(OG 카드), 조회수, 추천. 본문은 Markdown으로 저장한다.
* **댓글:** 작성/수정/삭제, 1-depth 대댓글, 실시간(준실시간) 업데이트. 대댓글이 달린 댓글을 삭제하면 스레드를 보존하기 위해 "삭제된 댓글입니다"로 표시한다(soft delete).
* **모바일 UI:** Bottom Navigation, 모바일 최적화 에디터.
* **초기 콘텐츠 시딩:** 운영자용 계정 약 20개를 Admin API로 사전 생성해, 오픈 초기에 게시글·댓글을 채운다 (ARCHITECTURE §5).

### 4.2 제외할 기능 (Phase 2 이후)
**A vs B 대결(투표)**, 소셜 로그인(Google/Kakao), DM, 팔로우, 활동 등급(티어 — 산정 기준은 데이터가 쌓인 뒤 결정), 아파트 상세 DB, 자동 매물 수집, 관리자 CMS, 실시간 AI 채팅.

## 5. Information Architecture
* **MVP:** **[홈] [인기] [글쓰기] [프로필]** (Bottom Tab 4개). Phase 2에서 [대결] 탭을 추가해 5개가 된다.
* **홈 피드 구성 (MVP):** 인기 게시글, 최신 게시글 순서로 배치. (Phase 2에서 "진행 중인 인기 대결"이 최상단에 추가된다.)
* **인기 산식 (MVP):** `created_at`이 최근 72시간 이내인 PUBLISHED 글을 `like_count` 내림차순(동률 시 최신순)으로 정렬. 별도 배치나 점수 컬럼 없이 인덱스만으로 구현한다.

## 6. 향후 확장 (Phase 2~4)
* **Phase 2 (A vs B 토론장):** 사용자가 모이면 대결 전용 게시판을 추가 생성한다 — poll 스키마 활성화(1인 1회 투표, 결과 게이지), [대결] 탭, 소셜 로그인(Google/Kakao), 활동 등급(티어).
* **Phase 3 (타임어택 리그):** 특정 시간(예: 금요일 22:00)에만 열리는 이벤트성 대결로 FOMO 유발.
* **Phase 4 (AI 아카이빙):** 리그 종료 후 Gemini API를 활용해 양측 논점을 추출하고 영구적인 SEO 페이지 생성.
